# 连续单卡资源假设下的范围建议

2026-11-02。用户提出假设：一张 L40S 可每天24小时持续使用到12月。本页是该条件下的
研究建议，不是已取得allocation、已续期或已执行新增实验的记录。现有v2协议、准备数据、
发布包和v1证据不变。

## 判断

现有v1＋待完成的v2＋CPU Decision Lab，足以形成内容完整的课程项目；是否取得某一成绩
还取决于课程评价和交付。若目标是利用一个月提高研究深度，当前范围偏保守，宜再扩一轮。
研究主问题保持为“何时直接使用decision model，何时转交值得其质量与系统成本”。

按11月2日至12月1日同一时刻估算，29×24＝696 GPU小时。当前v2主预测为10,800次调用，
36个开放到达单元仅有合计18分钟到达窗口。完整运行另计启动、smoke、预热、drain及恢复；
这些数不能转换为精确完成时刻，也不意味着应该消耗全部可用小时。

## 推荐新增范围

| 优先级 | 新内容 | 要回答的问题与边界 |
|---|---|---|
| 先完成 | 已交付的v2 | 小型gain/class-conditional政策是否比同目标预算的confidence政策更好？先保留完整正/负结果 |
| 高 | 一个较大生成式后级，优先验收Qwen3.5-9B | 当前级联收益有限，是否与后级能力/互补性有关？先在开发数据检查，不能预设9B更强 |
| 高 | 一个不同任务，优先考虑ANLI三类推断 | 结论能否超出意图分类和给定段落可答性？预先固定任务范围及fit/selection/test，不能按test挑容易赢的round |
| 中高 | StartLux9B作为规模匹配对照 | 在4B/9B两个规模观察decision与generative家族的差异；它是描述性系统比较，不隔离架构因果效应 |
| 中高 | CLINC上的TF-IDF＋线性分类器、冻结embedding＋线性头 | 4B是否优于真正便宜的任务专用替代？标注标签预算和训练成本，不能冒称同等零样本条件 |
| 中高 | 入选部署的更充分系统测量 | 轻载、近饱和和过载时，哪个部署满足SLO？每单元3–5分钟、至少5轮可作为新协议候选 |
| 可选 | 小型稳健性消融、受控live演示 | 候选顺序/措辞变化及真实新输入；CPU回放始终保留，不扩成多用户产品 |

新模型应固定revision、精度、提示、是否thinking和输出预算；不能通过隐式改变推理策略
把差异都归于模型规模。若要比较thinking，应单列有界预算的次要条件。新后级先报告直接
准确率、条件救回/误伤和代价，即使最终不纳入级联也保留其结果。

建议最终约三个任务家族、至多五个主模型配置、三个核心路由对照，加少量便宜基线。
不是所有模型×任务×政策×负载都做笛卡尔积；质量表可以稍宽，真实系统测量聚焦选定部署。

## 单卡限制与证据设计

更多GPU小时不会增加显存。9B独立运行、与4B同时驻留、稳定承受并发是不同验收；
不得由参数名称直接保证装得下。旧环境中0.4显存份额也不能直接照搬到9B。
先顺序采集可支持离线级联质量比较；两端延迟相加不能代替同卡真实级联性能。
若需量化，使用独立运行身份和匹配精度对照。

更大数据行数不自动增加独立证据。当前4,000条holdout仍只有57篇文章；重复相同问题
不增加独立样本量。新任务需审计已披露训练来源和重复输入，公开ANLI也不保证预训练未见。
新增政策不能在已见holdout上反复选优后称确认。扩展假设应在相应评价前写定；已看结果
的数据保留为探索，并另留确认集。现有v2的主比较不变。

系统测量可先用development定位饱和区，再固定正式到达率。比如4条件×5速率×5轮×
180秒＝5小时到达窗口，另加启动、预热、drain；并非需要连续一个月才能完成。
每个质量—性能工作点绑定实际同一政策和配置，明确质量/性能各自样本池。
可以另做一次有限时长稳定性运行，检查错误、队列和内存趋势，无需每个模型连续压测24小时。

## 建议节奏与停止条件

- 11/2–11/8：完成v2 GPU验收，开发区检查9B候选，固定新增任务/比较协议。
- 11/9–11/15：新任务和选定9B配置的质量采集；补便宜基线。
- 11/16–11/22：重点部署的稳态/饱和/过载测量和少量预定消融。
- 11/23–11/30：完成确认分析、报告、图、复现教程、演示与排练；停止新增研究轴。

这是建议分配，不是工期保证或已确认展示日。采用可恢复批次与一次性冻结分析，减少人工
盯运行的时间。开发区发现某后级没有足够互补性时，保留负结果，不为找正结果扩展无边界搜索。
正式测量不因某轮慢而挑选性重跑，停止规则在正式运行前写定。

## 相关工作与资料

学习路由和decision cascade已有研究，贡献应落在独立对照、适用边界、可靠的质量/服务
成本测量和可复现工具上，不能把新增一个logistic router本身宣称为首创。

- [RouteLLM](https://arxiv.org/abs/2406.18665)：学习强弱模型之间的路由。
- [JevCascade](https://arxiv.org/abs/2610.07716)：decision model的额外计算与置信度级联研究。
- [Qwen3.5-9B官方卡片](https://huggingface.co/Qwen/Qwen3.5-9B)：较大生成式候选，实际显存与本任务质量待验收。
- [StartLux9B Instant官方卡片](https://huggingface.co/startlux-models/StartLux-Decision-v1.1-9B-Instant)：同家族较大decision候选，官方速度来自其他硬件，不能用于本机性能结论。
- [ANLI官方仓库](https://github.com/facebookresearch/anli)：新增推断任务候选。
- [当前已冻结v2](V2_PROTOCOL_ZH.md)、[现有课程交付基础](FINISH_PROJECT_ZH.md)。
