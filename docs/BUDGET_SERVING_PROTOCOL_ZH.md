# StartLux 决策级联的在线预算与服务研究

2026-11-16，协议 `anli-budget-serving-v1` revision 1。用户已授权实现和节点执行；本文件固定实验设计，不代表软件测试、真实同驻留或 GPU 测量已经通过。机器可读数值与证据身份以 [budget_serving_protocol.json](../configs/budget_serving_protocol.json) 为准。

## 研究范围

本研究评价冻结 StartLux-4B → StartLux-9B 配对在实时后级调用上限下的质量与服务取舍。候选来自 [Study 4](../reports/learnability-2026-11-15/RESULTS_ZH.md) 已看过的次要结果：1,737题上的离线精确10%配额为1,290题正确，直接4B为1,263，直接9B为1,295。新的实时控制器不重现整批top10%排序，也不预先承诺相同准确率。

原模型、七维前级特征、拟合head、L2与阈值均不再搜索；不新增微调、量化、模型替换或评价任务。已见输入适合这项声明过的系统研究，不提供方法选择后的独立质量确认。

## 五个固定部署

| 条件 | 调用行为 | 显存份额 |
|---|---|---|
| `direct4b` | 每个接纳请求直接调用4B | 4B 0.90 |
| `direct9b` | 每个接纳请求直接调用9B | 9B 0.90 |
| `threshold` | 先4B，按原冻结gain阈值决定是否调用9B | 4B 0.40 + 9B 0.50 |
| `budget` | 原阈值候选，再受实时10%调用上限约束 | 4B 0.40 + 9B 0.50 |
| `random` | 先4B，独立Bernoulli(0.10)候选，再受相同上限约束 | 4B 0.40 + 9B 0.50 |

所有条件分配一张L40S；单模型与双模型的各引擎内存份额不同。这是部署取舍，不隔离模型大小、驻留或路由的单独因果效应。各引擎固定bf16、长度8192、`max_num_seqs=64`，不截断、不启用prefix cache。4B服务/引擎端口18380/18381，9B为18390/18391。4B native temperature为1.1103，9B为1.1014，沿用固定模型接口和标签顺序。

随机条件是前级运行后的转交，所有接纳请求先承担4B成本。标记按offer预先生成，种子独立于质量标签和线程完成次序。它与学习策略共用相同硬上限，但实际调用数可能更少，尤其发生拒绝时；实际比例必须报告，不因未用满额度修改概率。这不是对单模型结果作线性插值。

读取节点原 `results/aux-anli-learnability-v1-r2`，各文件SHA完整列在JSON中。只使用 `data/examples.jsonl` 中 `split=eligible_dev` 的1,737条、1,540个premise组；它们是原官方dev的已筛选子集。原gold文件有3,537个ID，新评价只能按这1,737个ID取标签。

旧阈值在selection转交87/900，在eligible-dev转交438/1,737。这些是历史回归值，不是新服务的必达数量。在线回答受执行条件影响可能变化，应保存真实阶段输出并评价。

## 实时预算的精确定义

令O(t)为本单元到时刻t已经到达的offer数，包括被客户端丢弃的请求；R(t)为已经发放的后级调用许可。`budget` 和 `random` 始终保持：

`R(t) <= floor(O(t) / 10)`。

调度器在判断是否接纳之前持锁登记每个offer；worker申请后级许可时，在同一锁内检查 `reserved < offered // 10` 并增加reserved。初始许可为零，不借用完整schedule中尚未到达请求的额度。该定义是墙钟时间上的累计到达前缀，不是任意滑动窗口，也不要求最终按原offer编号排序后的每个子集前缀满足相同约束。

前级可以乱序完成，许可按实际申请顺序分配；不等待未来分数、不重新排序。有效前级被预算拒绝时保留前级答案；失败前级是强制转交候选，但仍受相同上限约束，不能得到许可时保持请求失败。随机标记作用于有效前级，失败前级仍走同一受限恢复规则。

没有重试或退款，失败也消耗许可。许可发放后若共享期限已经耗尽而未真正调用后级，保留许可并明确记为未调用。报告reservation和actual attempt两种计数，不把它们混为一谈。预热、每个预检阶段和每个正式单元均使用新计数器。

保存带单调事件序号的offer/许可账本，以及candidate原因、granted/denied、许可前后计数、申请时已到达数、真实后级尝试和未使用许可原因。评价独立复算不变量，不能只信汇总计数或哈希收据。

## 正式矩阵与测量

固定10、20、40、80请求/秒，每单元120秒，3轮，共60单元。每轮内随机化负载顺序，每个轮次/负载内随机化五条件顺序；五条件使用完全相同的Poisson到达轨迹和打乱完整循环的输入序列。随机候选种子与轨迹种子分开固定。

客户端16 workers、最多64 in-flight；主SLO为500ms，次要SLO为1,000ms。每次HTTP最多一个attempt。调度延迟和客户端排队计入SLO；worker开始后分配 `min(30秒, drain剩余时间)`，两个模型阶段共享同一个单调期限。前级或后级返回时已超期，即便HTTP成功也记录deadline，不算成功；过期前级不再启动后级。输入窗口后最多drain60秒，父进程watchdog另有5秒grace，清理保留180秒。

每个正式单元重新启动相应服务、完成固定预热、测量、停止并核验归属和GPU残留。前级先启动，再启动后级；所有服务命令、资源配置和阶段结果都记录。只测量成功但停止未经验证的单元不算完成。

主要指标为该120秒offer窗口中真实及时且正确的回答数/120秒。逐格报告三轮值及median/min/max；三轮范围描述系统变异，不当作新的质量样本95%区间。另列全部offers、接纳、拒绝、失败、迟到、成功、全部offers正确比例、成功回答准确率及分母、实际9B调用率、许可计数、p50/p95/p99、队列与router时间、显存和allocation/card身份。

真实rescue/harm只在两个成功阶段答案都存在时计算，并标明适用分母；不可用历史counterfactual填补本次没有调用的后级答案。所有预定单元均报告，不挑最好负载宣称总体获胜。不得用离线准确率乘吞吐计算正确goodput。

## 自动预检、续跑和证据

单命令依次完成输入/源码核验、真实Slurm和原生进程归属检查、token覆盖与同驻留预检、全部60单元、冻结、评价与打包。正常成功阶段自动继续，无需用户阶段性交接。

预检包括：两个角色对全部1,737正式和90开发输入的无截断token验证；直接4B、直接9B、双模型部署各90条串行检查；各部署30秒、10请求/秒并发检查，双模型强制每条运行两个阶段；五个真实政策各10秒、10请求/秒的短烟测，计数器分别重置。双模型强制调用单独标为预检，不受正式预算限制、不混入正式trace。真实政策短烟测核对预算和接口，不要求学习策略必须转交某个数量或取得质量收益。

预检要求有效回答、无model/interface/timeout/deadline/client-rejection错误、load后健康、不同角色HTTP调用时间区间重叠（仅客户端in-flight，不作GPU内核并行结论）、预算核验、已确认停止和GPU清理。500ms SLO表现和正确率不作通行标准。读不到gold或不根据gold打分也不影响工程预检。

单角色启动最多1,200秒；一个完整attempt的绝对watchdog上界包含角色数×1,200、串行条数×30、该attempt全部并发/烟测窗口及drain、5秒grace和180秒清理。这是最坏情况安全上界，不是运行时长预测。启动慢、HTTP缓慢流式返回或worker阻塞仍须由拥有该进程的父控制器限时停止。迟于watchdog的完成收据不能变成成功。

会话时间从实际当前Slurm读取，限定有限的0到24小时，不使用用户手填HOURS_LEFT或旧deadline。剩余时间不足安全完成下一attempt时保存checkpoint；真正换allocation后，同一命令验证旧job已经终止再续跑。技术失败保存诊断并停止，不自动改显存、模型精度、阈值或预算策略。恢复同一科学身份的失败需明确重试；科学身份变化需新输出。11/23、11/30属于排期建议，不编码成过期阻断条件。

新输出独立为 `results/aux-anli-budget-serving-v1`。原结果、模型、环境和绝对路径绑定只读复用。导出紧凑包包含输入/router身份、代码/协议、原始offer与阶段回答、预算账本、进程/停止证据和分析；不含权重、环境、缓存或不相关旧实验。不能为了缩小体积省略审计所需trace。

所有正式trace和已确认停止冻结后才解释gold并评价；早期可只做文件哈希核验。这种次序保证程序边界，不把已见标签重新变成未见评价集。

## 实现定稿时确定的执行约定

2026-11-16 软件定稿时，以下未写成JSON数值的执行细节一并固定，正式运行前不再改动；数值协议JSON保持原样。
完整写法见[运行手册](RUN_BUDGET_SERVING_ZH.md#实验前固定的执行约定)。

- pair 预检经 runtime 的 `threshold` 条件启动，三个 pair 条件共用同一组 pair 控制。
- 每个运行控制各一份 tokenizer 报告，共四份，每份 watchdog 上限 1,200 秒。
- 随机候选标记使用字符串种子 `"20261116:random-candidates:r<repeat>-rate<rate>"`（烟测为
  `"20261116:random-candidates:preflight-smoke"`），按 offer 编号逐个取 `rng.random() < 0.1`；
  正式轨迹种子为 `20261116 + 1000×repeat + rate`，两类种子来源分开。
- 4B 回答可被冻结 adapters 解析、但被冻结 `front_features` 拒绝时，记为 `router_input` 失败，不申请许可、
  不调用9B，保留原始4B回答。
- 无法使用的 HTTP 200 正文（含 JSON `null`）记为带 `phase` 的 `invalid_response` 失败调用，留在全部分母中。
- GPU 驱动属于运行身份；驱动不同的节点不能混入同一研究，也不自动放宽。
- attempt 按完整 watchdog 上限预留时间；离线审计使用节点运行的同一份已发布源码；freeze 须与完整证据清单、
  token/预检/单元收据和源码指纹逐项一致。

## 解释和未完成事项

本研究没有实际美元费用测量。少调用9B不等于GPU账单按比例下降；每条件仍占一张L40S。一个部署有用的质量/预算/服务取舍不要求在某个指标上同时击败两个直接模型。

已见次要结果的候选选择可能有乐观偏差，逐格区间不能校正。旧Qwen服务采用ANLI官方test，不是本次eligible-dev的匹配对照。176份embedding的归档、完整text-head重拟合、另外的重拟合稳健性检查以及成员新环境复现仍是单独工作；本研究不宣称已经完成它们。节点同驻留、实际KV、服务延迟和最终实验结果均须在真实执行后验收。
