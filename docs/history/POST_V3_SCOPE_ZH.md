## 首选一轮研究：固定路由加在线预算约束

已有证据提供具体动机：V3 confidence 在 validation 转交10%，holdout转交23.219%；
V2在40请求/秒时，级联500ms SLO goodput约4.89/秒，直接StartLux约40.43/秒。
两个结果来自不同实验，不能直接当成同一条因果链；新实验要在同一设置下同时测量。

建议固定同一 confidence 分数与阈值，仅增加一个明确的在线后级预算控制规则，预算耗尽
时返回前级结果。窗口、额度、失败处理、起始余额和边界处理均须在协议写定；不要同时
改打分器、模型和多套调度规则。若以后再加排队感知，另作清晰消融。

候选最小系统矩阵：

| 轴 | 建议范围 |
|---|---|
| 模型 | 优先复用已验证的 StartLux4B + Qwen4B 共驻留配置 |
| 条件 | local-only；两模型驻留但仅用local；固定confidence级联；同级联加预算控制 |
| 到达负载 | 开发池定位轻载、临界、过载三个点，然后冻结 |
| 重复 | 每单元180秒到达窗口、5轮，四条件合计约3小时到达窗口 |
| 配对 | 使用相同输入/到达表，分块随机化条件顺序，记录每次allocation/设备边界 |
| 测量 | 实际转交、queue/dispatch、拒绝/超时、p95、SLO goodput、准确率、救回/误伤 |

3小时不含环境准备、开发摸底、启动/预热和drain，不能当完整工期。goodput 分母和计时
边界应保留 offered requests 与预定到达时间；同时报告在SLO内正确完成的比例/速率，
避免仅凭更快地返回错误答案宣称改善。标签只用于评价，不能作为在线控制信号。

硬上限达标是规则的设计性质，研究价值来自质量代价、到达顺序敏感性、排队/过载行为，
以及它是否值得超过直接local和resident-idle的部署成本。token bucket允许的突发量不能
写成任意窗口的严格百分比上限。也不能提前查看完整test流再用top-k冒充在线控制。

已见数据可做回放、开发或明确标注的系统工作负载；新政策在其上的质量是探索性结果。
如主张新政策泛化收益，需先审计一个未用于选方案、按来源/premise隔离的确认池并冻结
协议。不能把旧test重新切分就恢复“未见”身份，也不把公开新数据称为预训练未见。

9B仅验证了单模型运行。需要9B时先单独验收共驻留和并发；不让它成为该扩展的默认依赖。
V3 positive_gain零转交，重测它的级联性能主要重复local路径，不作为新系统实验主角。

## 一个可选方法实验：互补性是否能被更合适的特征识别

V3的Qwen9B能救回289道前级错题，但现有置信度/预测类别/长度特征得到的gain分数全为负。
这支持提出“特征是否缺少语义信息”的假设，不证明原因就在特征，也不保证oracle可达。

只预定一个增强候选，例如冻结文本embedding加正则化小头，与现有gain对照；监督标签
预算对齐，拟合/选择仅用开发角色，特征必须在后级调用前获得。embedding的推理时延和
资源成本也计入。先验证开发区有没有稳定、值得确认的互补性选择能力，再决定是否采新
确认数据；不在已经查看的ANLI test上轮流换模型直到得到正结果。

另一项低成本补充是 CLINC 的 TF-IDF+线性分类器，用于定位任务专用模型的质量/成本。
它使用监督标签，与零样本LLM条件不同，应单列训练预算；不作为新增大型任务矩阵的起点。
11/4该项已连同冻结MiniLM、400/1600两个训练预算完成；总体质量与银行/OOS交换见
[验收报告](../../reports/cheap-baselines-2026-11-04/RESULTS_ZH.md)，同口径服务性能仍待测。

## 范围与停止条件

- 推荐上限为一轮预算/系统主实验 + V1–V3完整Lab + 可复现仓库；语义router只留一个可选候选。
- 开发阶段服务改善不足或实现代价过高，可记录结果后终止候选；正式阶段保留所有预定
  单元，无论正负，不挑慢轮重跑。直接StartLux若仍占优，也构成清晰结论。
- 给新增研究一个预先约定的时间窗口，例如接下来7–10天；这是范围约束建议，不是工期
  保证。其后优先完成复现、报告、展示与排练，避免反复增加研究轴。
- 重复确定性质量推理不增加独立质量样本，更多GPU小时也不增加显存或解决已见holdout问题。
- 本建议未运行，未修改现有冻结配置，也没有声称该机制或新router必然优于当前结果。
