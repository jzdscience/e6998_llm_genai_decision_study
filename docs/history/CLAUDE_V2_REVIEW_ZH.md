## 总体判断

**采纳收敛范围的方向，修正其方法、统计和系统归因后再执行。** 如果按附件提出的紧范围、单人主导与提前收尾目标规划，优先做“旧任务诊断 + 补 Qwen fitting 数据 + fresh SQuAD 确认 + 小型系统对照 + CPU Decision Lab”，比上一版 ANLI 主线更省集成成本。ANLI 保留为另一个有效研究范围，不是设计错误，也不因为没有专门评分项就没有科学价值。

## 研究方法的关键修正

### 1. 先诊断正确，但不能把误差分解当因果归属

重新读取真实 SQuAD 2,000 条预测得到：StartLux 正确 1,825；Qwen 能救回 StartLux 错误共 66 条，能损害其正确结果共 171 条，其余 1,763 条净收益为零。冻结 gate 转交 125 条，实际救回 29、误伤 24，因此与同配额 oracle 的 61 条差距确实是 `37 漏救 + 24 误伤`。

但 24 条误伤也可以通过避免错误转交来减少，并不专属于“后级可靠性”；37 条漏救也不证明目前特征能识别它们。这个分解告诉我们要检查什么，不能直接决定必须建两种方法。固定转交集合的完美仲裁上限 `（1825+29）/2000=92.70%` 正确，但依赖知道哪些后级答案有害，属于 oracle 上界。

“三模型皆错”也只是当前三模型选择器无法纠正的部分，不能叫任务的不可约错误。

### 2. 二分类概率特征确实冗余，双头模型仍需比较

对二分类令 `q=max(p,1-p)`，margin=`2q−1`，entropy=`−q log q−(1−q)log(1−q)`。三者没有额外信息；不同变换可以改变模型基函数，但不能凭空获得后级能力信号。类别和长度仍可能提供信息，因此“必然退化为类别阈值”也过强。上一建议的 ANLI 是三类任务，不能直接套二分类结论。

`E[g|z]=P(Q正确|z)−P(L正确|z)` 是正确恒等式。若把后项直接换成温度校准后的最大概率，需要它对 z 中类别、长度等特征也具有条件校准；标量温度不保证这一点。可比较两个正确性模型之差与三类 gain 模型，但不能预先断言双头更稳。三类模型也使用全部样本，真实正收益类别只有 66/2,000，需要注意稀疏性。

### 3. 一致性和仲裁的成本、信息价值要分清

Kev×StartLux 一致性在已有离线预测中无需新采集；部署到新输入仍需多运行一个 4B 模型。现 runtime 只支持一个 decision model 与 Qwen 配对，三模型方案需要独立驻留/调度与成本计量。它可作探索性信号，但不列作默认的“免费特征”。实际 66 条可救回案例中，37 条两个 decision model 一致、29 条不一致，因此不一致信号并不覆盖全部互补性。

转交后的轻量仲裁可以不增加模型调用，但已经发生的 fallback 调用成本不会退回。对 SQuAD 二分类，如果规则只依赖前级特征与“是否分歧”，分歧时后级标签已被前级标签唯一确定；可以在转交前计算“若分歧是否听后级”。当答案为否时直接保留前级，最终预测与事后仲裁相同，却省掉无用调用。因此这一策略通常应视为更细的 gate 消融，而不是独立新增信息的方法。CLINC 多类中，后级具体候选标签可能提供新的仲裁信息。

## 系统建议值得加强，但原归因不成立

本轮对真实 benchmark traces 做了新增 CPU 分解，结果为三轮算术均值：

| SQuAD，并发 8 | StartLux direct | StartLux→Qwen |
|---|---:|---:|
| worker 开始到最终结果的平均延迟 | 137.59 ms | 179.01 ms |
| 前级阶段平均延迟 | 137.58 ms | 163.67 ms |
| Qwen 额外阶段，摊到所有输入 | 0 | 15.22 ms |
| 实际转交比例 | 0 | **5%** |
| 成功吞吐 | 57.88/s | 44.21/s |

正式 2,000 条测试的转交率为 6.25%，benchmark 的 200 个固定输入是 10/200=5%。不能混用。总延迟增加约 41.42ms，其中 26.09ms 出现在前级阶段的差异，15.22ms 是摊销的后级阶段，其余是少量外层开销。不能用 Kev 单请求中位数和假设的 Qwen 延迟解释 StartLux c8 的结果。

这些差异尚不能证明由 GPU 竞争、驻留、批处理或固定运行顺序中的哪一项造成。Little 定律描述平均占用、吞吐和时间之间的关系，不辨认变慢机制；`c/mean_latency` 还把并发上限近似成了平均活动数。用同一批聚合时间反推 `L=λW` 是记账关系，不能当独立因果验收。

因此采纳 resident-idle 对照，并把系统扩展限定在主 SQuAD 模型对、少量到达率和最终入选的政策。先不要同时扫两个任务、所有路由、多个内存比例、缓存和大量负载点。记录计划到达、实际提交、worker start、最终完成、拒绝/超时及独立占用计数，明确定义 warmup、测量与 drain 窗口。goodput 以所有 offered requests 为口径。

复算脚本与结果：[decompose_benchmark_timing.py](../../.validation/claude-review-2026-11-02/decompose_benchmark_timing.py)、[数值收据](../../.validation/claude-review-2026-11-02/benchmark-timing-decomposition.json)。这只是对已保存 traces 的分解，没有重新测速。

## 统计推断与 holdout

1. **已有统计推断。** v1 已报告文章簇配对 bootstrap 区间，不能从没有 McNemar/p 值推出缺少显著性分析。是否达到统计显著、效应多大、是否有实用意义需分开。
2. **普通 exact McNemar 不处理文章内相关性。** 把它称敏感性分析也不能使其精确性假设成立。若需要正式 p 值，应预定支持簇结构的检验；主要保留效应量与文章簇区间。[聚类 McNemar 方法研究](https://pubmed.ncbi.nlm.nih.gov/15236431/)
3. **4,000 条可抽，不等于能检测 0.6pp。** 原始数据哈希核验和去重后，57 篇项目未用 train 文章有 14,157 个问题，9,706 可答、4,451 不可答，只有 33 篇包含不可答问题。抽取 2,000+2,000 在原始数量上可行，但仍需输入长度筛查与明确问题/文章权重。不得仅凭行数保证功效。
4. 功效应指定 alpha、目标 power、政策不一致概率及簇内相关/效应异质性。仅示意地把 v1 级联相对 direct 的 53/2,000 不一致率当 IID 近似，双侧5%、80% power 时 4,000 条的近似 MDE 已约 0.72pp；这仍不是新策略或文章聚类下的功效计算。正式设计应采用非 test 的信息或敏感性区间。
5. 未显著不等于等价。“排除大于 X pp 的改善”需要有效上界低于 X；正式等价结论需要预定界限与相应推断，不是负结果的默认写法。

57 篇来自原 train，v1 主测试来自官方 dev；新 holdout 可以比较同一新样本上的冻结政策，但不能冒称复现了相同来源总体。原 CLINC 已见测试继续做探索，不能当新方法的确认集。

## 执行顺序必须调整

附件先在阶段 3 测 openloop，再在阶段 4 拟合政策，会导致测不到最终 v2 政策的系统表现。建议改为：

1. CPU 诊断、数据协议、工程 dry run、CPU Lab 初版。
2. 补 Qwen 的 cal/val。保留两任务开发时为 2,800 条；若只做 SQuAD，则其部分为 2,000 条。
3. 在同一次 allocation 中完成 CPU 拟合、selection 和 policy freeze。
4. 对已冻结的最终在线政策做小型系统测量；独立标记固定批次 top-k 的离线政策。
5. 最后按协议评估新质量 holdout。若提前采集其预测，应隔离 gold、指标和挑例输出；性能开发工作负载不能偷偷使用封存 holdout 来选政策、到达率或配置。

**不能仅按转交率拼 accuracy–goodput 曲线。** 两个 10% 政策可能转交不同长度与难度的输入。每个联合工作点须属于同一政策/config，以及按协议匹配的质量与性能工作负载；若性能只用子样本，说明抽样和误差边界。未经真实测量的政策只画离线质量/预算曲线。

同预算比较也要先定义基线。原 P1 是验证风险 gate，在 v1 SQuAD 正式测试上实际转交 6.25%，不能直接称 10% 预算基线。保留原 P1 为冻结参照，另定义同配额置信度 top-k，或在 selection 上固定目标转交率的在线阈值；后者在 holdout 的实际转交率可能偏离目标。不要按 holdout 重新调在线阈值来强行凑配额。

JevCascade 已研究决策模型级联优于重复询问自身的情形；这限制新颖性表述，不要求课程项目发明新架构。原 proposal 已把独立可复现实证作为贡献，现有校准/路由/批处理也已有消融。[JevCascade](https://arxiv.org/abs/2610.07716)

## 推荐的缩小版本

- **主线**：SQuAD 的原 gate、按类别 gate、一个简单 gain 方法。必要时加二分类仲裁的等价 gate 消融；其余候选先在 selection 淘汰。
- **系统**：StartLux 单独、StartLux+闲置 Qwen、最终政策级联、Qwen 单独；少量预定到达率。暂不同时扩内存与缓存轴。
- **确认**：预先封存的新 SQuAD 文章集合，主比较一个，区间与样本角色明确；CLINC 保持探索性。
- **展示**：CPU Lab + tutorial + 关键行为测试；实时服务可选。
- **可选模型**：StartLux9B，仅在核心链路完成、实际资源允许时采集；不把其更强或运行时长列为既定事实。
