## U2 · P2：新双服务控制器必须有独立的生命周期约定

位置：设计稿第 55–58、107–110 行；`decision_study/runtime.py:800`；
`decision_study/size_control/runtime.py:317`、`:344`。

分别调用 V1 单模型 launcher 会跳过它的双模型容量与 0.40 限制，因此新控制器必须显式承担以下检查：

- 第一服务启动前核实实际 Slurm allocation、单张 L40S 和 GPU 空闲；第二服务启动前只允许本次已启动前级的
  进程组及其后代，拒绝无关 GPU 占用。
- 两服务使用独立 runtime-control 根目录、端口及元数据。V1 会写本控制目录的 `last_services.json`，不能共用根。
- 共同外层生命周期清理，例如 `ExitStack`。后级启动失败也要清理前级；单元失败、超时或中断都清理自有进程，
  不停无关服务。每单元结束确认后端已停止，不仅等待客户端 drain。
- 不能直接嵌套现有 `size_control.runtime_context`，它每次进入都拒绝任何 GPU compute PID，第二次会撞上前级。
  也不能改写旧规模对照的 0.80 控制记录来运行 0.50。
- 新输出目录绑定新协议/源码/环境/模型身份；旧 runtime 发现兼容逻辑、安装记录与锁保持只读复用。

这些是新控制器需要实现和测试的约定，目前没有 GPU 成功运行证据。

## U3 · P2：明确一次请求的共同执行预算

位置：设计稿第 73、76–79 行；`decision_study/service_study/measurement.py:107`。

复用的 `run_cell` 在 worker 开始执行时才给予 `min(30 秒, drain 剩余时间)`，此前的客户端排队不计入这
30 秒，但 SLO 从预定到达起算，包含排队。推荐保持这一现有语义，并在 Markdown/JSON 中写明。

级联两阶段共享一个 monotonic deadline，后级只获取前级和路由结束后的剩余预算，不能重新获得 30 秒。
前级失败时仍遵守预算；预算用尽即记录 deadline，不再强制调用后级。后级失败不得悄悄回退成前级成功。
调用超时与客户端 drain 之外仍需要外层 watchdog；普通 HTTP timeout 不等于整条调用链的硬性完成期限。

## U4 · P2：历史重放是回归检查，实时差异是测量结果

位置：设计稿第 19–20、52–53、94–95 行；JSON 的 `comparisons`。

10/s × 120 秒平均只有约 1,200 次 offers，没有覆盖全部 3,200 题；过载拒绝又改变成功响应的样本组成。
因此不能把实时成功响应准确率必须等于 74.19%/76.69%/74.41%，或实时转交数必须等于 766，设为验收条件。

- correct goodput 必须逐条使用真实返回标签，分母为 120 秒；同时报告全部 offers、接纳、成功、及时成功、
  正确、及时且正确、拒绝、失败和晚返回，不能用历史准确率乘吞吐。
- 历史对照按同一实际 offer/成功响应 ID 和出现次数加权；区分完整历史池准确率、匹配子集的历史准确率和本次结果。
- 保存 live label、概率、route 与历史记录的差异以及重复请求变化。合法差异不触发调阈值、丢弃差轮次或择优补跑。
- 独立重放确认原 3,200 条预测的 class_conditional 为 766、confidence 为 743。此数只用于历史单次完整池回归。

实现时还有一个具体接口差异：`ModelClient` 返回 `model="startlux"`（`adapters.py:159`），V3 router 要求
`model="startlux4b"`（`v3/policies.py:63`）。显式规范化模型角色并核验真实 checkpoint，保留原始响应与状态；
不要把错用模型或 schema drift 静默包装成合法前级失败。真实调用失败与 router 输入格式错误要可区分。

使用整份 V3 冻结政策，阈值保留 `0.272907934835248`，不能只复制正文四位小数或对实时整池重新 top-k。
冻结文件 SHA 为 `28efefe7814ef234e5ea96503386b577b1db34e6acafa90b57f421e5f39acf50`。
每条 offer 关联前级/后级独立 request ID、状态、时间、概率、路由原因及最终标签，支持独立重放审计。
