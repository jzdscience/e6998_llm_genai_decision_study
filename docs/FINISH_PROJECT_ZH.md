## 结果叙事与报告结构

原proposal的研究问题是“When Can Open Decision Models Replace Generative LLM Calls?”。
结果支持一个有条件的回答：StartLux在本次冻结分类任务上同时具有较好的直接质量和服务效率；
置信度转交能改善较弱的Kev，但没有带来超过最强直接模型的可靠质量增益，而且可能降低吞吐。
验证集5%经验风险约束没有普遍迁移到测试集，不能把高覆盖率解释为已保证的低风险替代。

建议报告按以下逻辑写作：

1. **问题与贡献。** 强调独立系统评价、概率校准和实际级联成本，保留负结果；不声称新架构。
2. **相关工作。** 逐项核对proposal引用及固定版本，与本文的独立复现、风险迁移和系统测量区分。
3. **方法。** 解释划分/文章隔离、等价任务信息、温度与gate的拟合来源、失败计数、配对bootstrap，
   以及相同转交配额的随机/oracle。说明这是系统比较，无法隔离架构或预训练数据影响。
4. **结果。** 先呈现主终点coverage与实际接受错误率，再给出direct质量、级联净纠错、校准、
   OOS压力结果，最后加入真实吞吐/延迟。正式测试与200输入benchmark保持各自分母。
5. **限制。** 公共数据暴露未知、验证风险不保证测试风险、固定单设备/顺序/工作负载、三次重复，
   worker计时不含控制器队列和启动开销，以及已观察到的Kev并发标签变化。
6. **复现与结论。** 给出版本/文件哈希、执行命令、分析与demo入口，陈述哪些条件下级联值得使用。
