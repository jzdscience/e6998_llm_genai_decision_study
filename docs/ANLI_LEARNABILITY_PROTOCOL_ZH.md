## 第一阶段已发现的问题

固定 ANLI 源 ZIP SHA 为 `e5c058f2bb4e6190b0651badca2c590e45db95248f8b28cde674615ee40820bf`。
V3 的历史准备输入含 5,990 条，除 fitting/selection 外还包括开发与旧 test。逐 UID 不重叠并不足以保证独立，
因此按 NFKC、casefold、空白规范化后的 premise 和 input 哈希排除历史使用。

| official dev 来源 | 原始条数 | 当前可用候选条数 | 保留比例 |
|---|---:|---:|---:|
| R1 | 1,000 | 374 | 37.4% |
| R2 | 1,000 | 484 | 48.4% |
| R3 | 1,200 | 879 | 73.25% |
| 合计 | 3,200 | 1,737 | 54.28% |

这 1,737 条对应 1,540 个不同 premise 组。R3 在保留池中的比重由原始 37.5% 升至约 50.6%。
这些是输入审计结果，不是模型性能。Codex 用不导入新审计器的独立脚本复算了相同的候选数与组数。
本机完整盘点及可重复执行入口见[审计与运行说明](RUN_ANLI_LEARNABILITY_ZH.md)。其他机器／队员的额外使用
仍需单独登记；本机找不到记录不能证明外部没有使用。

本机 UID 盘点覆盖 29,530 个文本文件、16,436 个 ZIP 成员和 517 个 Git 历史文本 blob。独立的无 ID
文本核对在先前清单中的 46,478 项产物上搜索精确规范化 premise，并解析结构化及转义 prompt 字符串；
未发现额外命中。三个开发中的文件按实际新字节核对并登记差异。该检查不覆盖语义近重复、任意编码或拼接字符串、
二进制文档和其他机器，不能替代上述外部使用登记。见[输入审计记录](../records/anli-learnability-preparation-2026-11-12/input-audit.json)。

筛选改变了目标总体。**主估计对象固定为审计后保留的 official-dev 子集**，按其中每道问题等权；
不能把结论写成对完整原始 dev 的无偏估计。按官方 round 比例 31.25% / 31.25% / 37.5% 加权只作预定敏感性分析，
它不能恢复被排除的样本，也不能消除 round 内选择差异。逐类登记历史抽样是否使用标签或模型结果。
旧 V3 fitting 的 round/class 平衡依赖训练标签，选例规则在旧模型预测前固定；其他历史复制品不能一概视为新独立使用。

## 调整拟合量，但不更换主问题

即使允许复用合规历史 train fitting/selection/development，排除 official-test premise 与新 dev 候选 premise 后，
R1 contradiction 也只有 2,447 条；24,000 条九个 round/class 等额拟合至少需要各约 2,667 条，尚未计入新保留池
与 selection。因此原 1,800 / 8,000 / 24,000 建议不能原样执行。

现在优先考虑 **1,800 / 6,000 / 18,000** 的嵌套、等额学习曲线。18,000 仍需在实际 whole-premise
角色分配后验证每格至少 2,000 条；当前只是可行候选，不能宣布已经准备好。若分组后仍不足，先修订协议并记录原因，
不借用评价组、不偷偷补样、不根据新评价分数选择训练量。拟合标签和 selection 标签分开计数。

新 train 来源保留池必须排除全部历史 USED 组，与 eligible dev、fitting、selection 彼此隔离；
拟合池不需要全部换成历史从未使用的 train 样本。源 train 标签可以用于拟合配额可行性检查，
不能据此声称未来抽出的 train 保留池标签从未被程序解析。

## 主比较与对照

主比较保持 StartLux-4B → Qwen3.5-9B，最大预定拟合量，在保留 dev 上比较两臂：

- 前级置信度、预测类别、输入长度。
- 同样信息加一个冻结文本表示。

两臂使用同一家族的净收益学习器、相同拟合与 selection 数据、相同优化和调参预算。候选实现为两个正确性 logistic
head 的概率差；具体正则、求解器和特征版本在正式冻结时固定。文本编码器候选是现有固定 revision 的
`all-MiniLM-L6-v2`，不是本轮再搜索多个 encoder。

其固定[模型卡](https://huggingface.co/sentence-transformers/all-MiniLM-L6-v2/blob/1110a243fdf4706b3f48f1d95db1a4f5529b4d41/README.md)
披露了 SNLI、MNLI 等训练来源；这不证明与 ANLI 没有逐样本重叠。正式协议记录已知训练来源和未知暴露，
不把“不能确认完全未见”写成已污染，也不因为找不到完整预训练清单就声称换一个模型能解决问题。

主终点是精确离线 `floor(0.1*N)` 转交配额下的配对准确率差，预定 sample ID 同分规则。
最低置信度 10%、同配额 random、同配额 oracle、直接 4B/9B 为对照。另一个后级 StartLux-9B、其他训练量和
新 train 来源保留池属于次要结果，不能因某个显著值而升级为主结果。

路由时不能使用后级回答、gold、reason、verifier 或采集模型正确性字段。前级失败的强制转交计入调用配额；
若仅失败样本就超过配额，主单元按预定技术失败处理，不能悄悄放宽预算。

区间按 premise 做配对重采样，重采样批次重新执行配额排序，条件于已拟合模型。正式协议需固定 bootstrap 次数、
种子、置信水平及最小有用效应。1 pp 暂作为待论证候选，而非已经批准的等效边界。低功效时仍报告原主终点及区间，
不改到更有利的 train 保留池；不把“不显著”写成“等效”。

部署阈值允许零转交，实际转交率、相对直接 4B 的净收益及相对直接 9B 的质量／成本单独报告。
离线 top-k 不代表实时严格预算，也不代表值得部署。

## 开发期 GPU 预检

新入口只复用旧 V3 的 **90 条 development 输入**，它们来自 official train，已经在历史实验中使用。
顺序启动 StartLux4B、Qwen9B、StartLux9B；每次只驻留一个模型，显存份额 0.8、max-num-seqs 64、最大长度 8192。
该配置有独立身份，不冒充旧服务研究的 0.4/0.5 份额。

保存输入与源码哈希、精确 token 报告、实际启动命令、模型/环境身份、原始响应、耗时、资源观测和停止核验。
不读取评价 gold、不输出新准确率、不训练 router。只有采集完整、退出及时、服务停止通过才接受该角色；
失败尝试保留，重试需显式参数，换 allocation 核实旧作业终止及新作业真实余量。

90 条旧开发样本适合检验运行兼容性及取得初始成本，但不能代表整个拟合池的长度分布，不能作为最终训练耗时保证。
必要时再在已分配好的 train fitting/selection 块内做代表性成本采样，不借用新评价池。

## Claude max 参与与独立取舍

实际 Claude Code Opus 5.5、max effort 起草了八项开发期验收条件，并在看到输入审计摘要后指出保留池组成改变的风险。
Codex 据此固定了保留子集的主估计对象与 round 敏感性分析。Claude 没有直接读取原始数据或独立验收代码。

第三轮实现设计讨论中，Claude 指出子进程收养可能分多次发生，不能只凭一次快照判断清理完成。
Codex 的独立代码审阅另发现 PID 复用、socket timeout 语义和耗时汇总复算问题；这些作为节点发布前的检查项处理。
完整提问与答复见[第一阶段 Claude max 记录](../records/anli-learnability-preparation-2026-11-12/claude-protocol-discussion.md)。

未采纳其草案中的自动规则：拟合也排除所有历史使用、程序解析过标签就宣布评价作废、按预期 SE 更换主终点、
未知上游暴露就必须换 encoder，以及为开发预检重跑整个旧 test 并要求百分比匹配。也没有采纳未经验证的
Jaccard 0.8 近重复阈值。当前隔离保证限于声明的规范化精确 premise/input，不能升级成语义近重复零重叠保证。
